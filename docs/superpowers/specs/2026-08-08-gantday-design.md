# GanttDay 设计规格

**状态：** 待用户审阅  
**日期：** 2026-08-08  
**工作名：** GanttDay（可改）

## 1. 产品定位

面向自由职业者 / 创作者的个人甘特日程管理器。主价值：在时间线上看到「什么时候做什么」。

| 项 | 决定 |
| --- | --- |
| 平台（v1） | **仅 Windows**（exe / msix 直装） |
| 平台（延后） | 华为 MatePad 鸿蒙 6（纯血，不能装 APK）；用「适度预留」降低移植成本 |
| 用户模式（v1） | 纯单人、纯本机；Windows 与其他设备互不同步 |
| 分发（v1） | Windows 安装包直装；不上商店 |
| 调试设备 | Android 真机可用于将来；v1 不交付 Android / 鸿蒙包 |

### 1.1 范围节奏

- **v1：** 本地任务 CRUD、日 / 周 / 月视图、标签过滤、导入导出备份、完成对照（计划 vs 实际）
- **v1.1：** 提醒通知、导出图片 / PDF
- **v2：** 账号、云同步、共享项目与共同编辑

### 1.2 v1 明确不做

重复任务、全天任务、提醒、依赖 / 里程碑 / 关键路径、账号 / 云同步 / 多人、系统日历读写、执行人 / 「谁」、鸿蒙 / Android 安装包。

## 2. 信息架构与视图

- **扁平任务 + 多标签**；创建时可选 **主标签（primary）** 决定基础色相
- **无执行人字段**
- **日 / 周：** 横向时间轴，小时网格，**吸附 15 分钟**
- **月：** 每天最多显示 2–3 个任务标题，超出 `+N`；点击某天进入日视图
- **默认可视时段：** 8:00–22:00（设置可改）
- **不同任务时间重叠：** **并行分行**（各占一行）
- **同一任务的计划条与实际条：** **同一行内层叠**（见 §5）
- **跨午夜任务：** 数据仍是一条；绘制时按日切成两段（当天画到 24:00，次日从 0:00 接着画）

## 3. 架构与模块边界

目标：v1 只做 Windows，但为将来鸿蒙移植预留薄平台边界（约 10–15% 额外工作量）。

### 3.1 界面层（Flutter）

日视图甘特、任务表单页、完成弹层、设置页。只调用领域层与平台接口；不做时间换算或颜色计算。

### 3.2 领域层（纯 Dart，零平台 / 零 Flutter 依赖）

移植时原样搬迁。

| 模块 | 职责 |
| --- | --- |
| `GanttGeometry` | 可视时段 ↔ 像素换算；15 分钟吸附（四舍五入到最近刻度） |
| `DaySegmenter` | 给定任务与日期，输出落在该日内的时间段（跨午夜切段） |
| `LaneLayout` | 重叠任务分行；首尾相接（如 12:00 结束与 12:00 开始）**不算重叠**，可同排 |
| `UrgencyPalette` | 色相 + 紧迫度 + 完成状态 → 计划条色、实际条色、是否逾期斜纹 |

### 3.3 平台层（移植时重写实现）

界面与领域层只依赖接口签名：

| 接口 | v1 实现 |
| --- | --- |
| `TaskRepository` | SQLite：按日期范围查询、增删改、完成 / 撤销完成；变更以数据流推给界面 |
| `SettingsStore` | SQLite：可视时段、紧迫窗口天数、标签默认色等 |
| `FileGateway` | Windows 文件选择对话框：读 / 写备份文本 |

## 4. 数据模型与存储

### 4.1 时间表示

- 存 **本地墙钟时间**（不带时区），单位为自纪元起的 **分钟整数**（不做 UTC 换算）
- 原因：个人日程的「9:00」必须永远读作 9:00；时区变化不得平移条形
- 精度：分钟级，满足 15 分钟吸附；整数便于排序与范围查询
- v2 若需跨时区同步，再增加时区字段，不改现有语义

### 4.2 任务

| 字段 | 说明 |
| --- | --- |
| `id` | UUID（为将来同步预留，避免自增撞号） |
| `title` | 任务名 |
| `plannedStart` / `plannedEnd` | 计划起止（墙钟分钟） |
| `actualStart` / `actualEnd` | 实际起止（可空；仅已完成时有值） |
| `isCompleted` | 是否完成 |
| `primaryTagId` | 主标签（可空） |
| `autoHue` | 无标签时创建时随机生成并持久化的色相；有标签时可空（色相跟标签） |
| `overrideHue` | 手动覆盖色相（可空）；只改色相，不取消紧迫度 / 置灰逻辑 |
| `note` | 备注（可空） |
| `createdAt` | 创建时间 |

任务与标签多对多（关联表）；主标签另存 `primaryTagId`。

### 4.3 标签

`id`、`name`、`defaultHue`。

### 4.4 设置（键值）

- 可视时段起止（默认 8、22）
- 紧迫窗口天数（默认 7，可配置）
- 其他本地偏好

### 4.5 查询与颜色

- **按日查询：** `plannedStart < dayEnd AND plannedEnd > dayStart`（能命中跨午夜任务）
- **同标签基础色一致：** 同标签任务基础色相相同；深浅差异 **只** 由紧迫度产生（不按任务 id 做随机深浅偏移）
- **无标签任务：** 创建时随机色相且避开已有标签色，**必须持久化**，否则每次打开变色
- **绘制辅助：** 条形间隙 + 略深描边，避免同色邻接难分界

### 4.6 备份

- JSON：版本号、导出时间、全部任务、标签、设置
- 导入：整体校验 + 事务；失败则整批拒绝并列出问题行
- 已存在 `id`：**默认跳过并汇报**，不覆盖

## 5. 颜色与完成态视觉

### 5.1 色相来源

1. 有手动覆盖 → 用 `overrideHue`
2. 否则有主标签 → 用标签 `defaultHue`
3. 否则用持久化的 `autoHue`

### 5.2 未完成紧迫度

- 从创建起即按「距计划结束」计算鲜艳度（未到计划开始也会渐艳）
- **紧迫窗口：** 默认 7 天，设置可改；窗口外恒定最淡
- **渐变曲线：** **线性**（颜色深浅对应剩余时间在窗口内的比例）
- **逾期未完成：** 鲜艳度封顶不再变；加斜纹 / 描边 / 小图标；**条形停在原计划位置，不随当前时间拉长**
- 完成状态仅由用户手动标记触发（不自动完成）

### 5.3 已完成：计划与实际同层叠合

- **计划条：** 原色置灰，粗条，位置锁定在计划起止
- **实际条：** 单一高饱和色（色相仍来自 §5.1；**不再**随紧迫度变化；**无**「超出段另色」），更细，居中压在计划条上
- 偏差靠错位阅读：实际伸出计划外 = 提前 / 超时；缩在内 = 提前做完；完全错开仍同排
- 主视图中 **已完成任务不可拖动**；要改计划须先撤销完成；要改实际可再开完成弹窗

## 6. 交互

### 6.1 创建与编辑

- 日 / 周空白处 **拖拽画块**，松手填标题；同时提供「新建」按钮进表单
- 拖条身改期、拖两端改时长；均吸附 15 分钟
- 最短时长 **15 分钟**；拖拽不得产生负时长
- 跨午夜任务任一段被拖 = 整条任务移动，两段一起动

### 6.2 完成弹窗

触发：甘特上点「完成」。

结构：

1. **统一固定语义的时间轴标尺**（见下）
2. **底层计划参考条：** 置灰、缩小弱化、不可拖；起止严格等于原计划
3. **上层选区框（唯一可操作）：** 左右手柄调实际起止；默认 = 计划区间
4. 选区可完全包裹 / 部分重叠 / 完全错开计划区间
5. **仅在弹窗内：** 超出计划区间的选区部分用高饱和色 + 可选箭头提示；确认后主图 **不保留** 分段高亮色

时间轴行为：

- 初始范围：计划区间上下各约 1 小时（打开时）
- **正常拖动时轴不动**
- 选区将越过弹窗边界时：**缩小刻度 + 视口平移**，使完整选区留在可视区内
- **拖动中只缩不放；松手后按最终选区重算一次** 最合适刻度并平滑过渡
- 缩放下限：约 **15 分钟 ≥ 8px**；触底后不再缩小，允许选区暂时出视口，靠数字读数
- 拖动中 **实时显示精确起止时间文字**

确认后：关闭弹窗；主甘特显示灰计划 + 单色细实际条叠合。可事后改实际时间，可撤销完成（撤销须清除实际起止）。

### 6.3 吸附与重叠判定

- 吸附：四舍五入到最近 15 分钟（如 8:07→8:00，8:08→8:15）
- 首尾相接不算重叠，可同排

## 7. 错误处理

| 场景 | 行为 |
| --- | --- |
| 数据库打不开 | **禁止静默建空库**；说明原因；提供「备份损坏文件并新建空库」选项 |
| 写入失败 | 回滚 UI 到操作前，明确提示失败（含拖拽改期场景） |
| 导入失败 | 整批拒绝 + 问题列表 |
| 导入 id 冲突 | 跳过并汇报跳过条数 |

## 8. 测试策略

- **重点：** 四个领域模块的确定性用例（吸附边界、跨午夜切段、分行含首尾相接、紧迫度 / 逾期 / 完成置灰）
- **存储：** 内存库；验按日查询含跨午夜；验完成 / 撤销字段干净
- **界面：** 少量测拖拽建块时间、完成弹窗返回的实际时间
- **不做：** 端到端 UI 自动化（单人项目维护成本高、回报低）
